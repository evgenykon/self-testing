# Self Testing

Статический сайт с тестами по разным темам: Nuxt 4, Tailwind CSS 4, KaTeX, Docker Compose и Makefile.
Все команды выполняются внутри контейнеров, результат сборки — статика для GitHub Pages.

Действующий сайт: <https://evgenykon.github.io/self-testing/>

## Возможности

- Список тестов по темам и сайдбар с индексом страниц (1 страница = 1 тест)
- Три типа вопросов: один правильный ответ, несколько ответов, ввод ответа
- В вопросах и ответах: markdown, изображения, формулы LaTeX (KaTeX)
- Таймер на тест или на каждый вопрос, прогресс-бар сверху
- Баллы 0/1/2, страница результатов с разбором ответов
- Перемешивание вопросов и вариантов при каждом запуске, сброс ответов и времени
- Ответы вшиты в страницу и обфусцированы (XOR + Base64, ключ генерируется на сборку)
- База тестов хранится в markdown-файлах, сборщик превращает её в статику
- История попыток в браузере: страница «Результаты» с графиками по тестам, сводкой и сбросом
- Кнопка «Я не знаю»: вопрос с правильным ответом попадает в список для разбора на отдельной странице

## Требования

- Docker с плагином Compose (`docker compose version`)
- GNU Make

## Быстрый старт

```bash
make install   # собрать образ и установить зависимости
make dev       # dev-сервер: http://localhost:3000
```

Статическая сборка и предпросмотр:

```bash
make build                 # .output/public, baseURL = /
make preview               # http://localhost:8080
make build BASE_URL=/self-testing/   # сборка под подпуть GitHub Pages
```

Проверки:

```bash
make test        # vitest: парсер, баллы, обфускация, перемешивание
make lint        # eslint
make typecheck   # vue-tsc
make shell       # shell внутри контейнера
make clean       # удалить контейнеры, volume и артефакты
```

> `make install` нужен после изменения `package.json`: зависимости лежат в docker-volume
> `node_modules` и обновляются командой `npm ci` внутри контейнера.

## Формат тестов

Один файл `content/tests/<slug>.md` — один тест. Имя файла становится URL: `/tests/<slug>`.
Допустимы строчные латинские буквы, цифры и дефис.

### Метаданные (frontmatter)

```yaml
---
title: Основы JavaScript      # обязательное название
topic: Программирование       # обязательная тема (группирует тесты в сайдбаре)
description: Краткое описание # необязательное
timer:
  mode: none                  # none | test | question
  seconds: 600                # для mode: test — время на весь тест
  perQuestion: 30             # для mode: question — время на каждый вопрос
shuffleQuestions: true        # необязательно, по умолчанию true
shuffleAnswers: true          # необязательно, по умолчанию true
---
```

### Вопросы

Вопросы задаются фенсед-блоками `:::question{type=...}`. Поддерживаются три типа:

````markdown
:::question{type=single}
Сколько будет $2+2$?

- [ ] 3
- [x] 4
- [ ] 5

:::explanation
Необязательный разбор, показывается на странице результатов.
:::
:::

:::question{type=multiple}
Выберите чётные числа:

- [x] 2
- [ ] 3
- [x] 4
:::

:::question{type=input}
Столица Франции?

:::accepted
Париж
Paris
:::

:::partial
^париж.*
:::
:::
````

Правила:

- `single` — ровно один вариант `[x]`, минимум 2 варианта
- `multiple` — минимум один `[x]` и минимум 2 варианта
- `input` — блок `:::accepted` (точные ответы) и/или `:::partial` (регулярные выражения, дают 1 балл);
  варианты ответа недопустимы
- В тексте вопроса, вариантов и разбора работает markdown: `**жирный**`, `` `код` ``, списки, ссылки,
  изображения, таблицы
- Формулы LaTeX: `$...$` — строчная, `$$...$$` — блочная (можно в одну строку или на отдельных строках)

### Изображения

- Из `public/`: `![подпись](/images/foo.png)` — путь автоматически дополняется baseURL
- Рядом с тестом: положите файл в `content/tests/assets/<slug>/` и ссылайтесь как
  `![подпись](./assets/foo.png)` — при сборке файл копируется в статику

### Баллы

| Ситуация | Баллы |
| --- | --- |
| Один ответ: верно | 2 |
| Один ответ: неверно / нет ответа | 0 |
| Несколько: все верные и ничего лишнего | 2 |
| Несколько: подмножество верных без ошибок | 1 |
| Несколько: есть любой лишний вариант | 0 |
| Ввод: точное совпадение с `:::accepted` | 2 |
| Ввод: совпадение с `:::partial` (regex) | 1 |
| Ввод: иначе | 0 |

Сравнение ответов не зависит от регистра и лишних пробелов, `ё` приравнивается к `е`.

### Поведение таймеров

- `mode: test` — таймер на весь тест; по истечении тест завершается автоматически,
  неотвеченные вопросы получают 0. До завершения можно свободно перемещаться по вопросам.
- `mode: question` — таймер на каждый вопрос; назад вернуться нельзя. После истечения времени
  ответ фиксируется, появляется кнопка перехода к следующему вопросу. Перезагрузка страницы
  начинает тест заново с перемешиванием.
- `mode: none` — без таймера.

### Результаты и разбор

- Каждая завершённая попытка сохраняется в localStorage браузера: баллы, процент, дата и длительность.
- Страница «Результаты» (`/stats`) показывает сводку, сравнение тестов и график процента по попыткам
  для каждого теста; там же кнопка сброса истории.
- Кнопка «Я не знаю» во время теста сохраняет вопрос с правильным ответом и разбором и переходит
  дальше (ответ не засчитывается). Отмеченные вопросы собраны на странице «Разбор» (`/review`),
  откуда их можно убрать по одному или очистить весь список.
- Данные не покидают браузер и не синхронизируются между устройствами.

### Генерация тестов из материалов

Промпт для LLM, который превращает любой файл или веб-страницу в тест нужного формата,
вместе с полным описанием формата: [docs/prompt-to-test.md](docs/prompt-to-test.md).

## Как это устроено

```
content/tests/*.md          исходники тестов (единственный источник правды)
scripts/build-content.ts    сборщик: парсит markdown, рендерит KaTeX/markdown в HTML,
                            обфусцирует payload и пишет app/generated/*
shared/                     чистые функции, общие для сборщика и рантайма
app/                        Nuxt-приложение (страницы, компоненты, composables)
app/generated/              генерируется при сборке, в git не хранится
public/tests-assets/        копии изображений, привязанных к тестам
tests/                      юнит-тесты vitest
```

Пайплайн: `npm run content:build` → `nuxt generate` → `.output/public`.
Обфускация: payload теста (вопросы, ответы, разбор) сериализуется в JSON, шифруется XOR-потоком
со случайным ключом на каждую сборку и кодируется в Base64. Ключ вшивается в бандл, поэтому это
защита от беглого просмотра исходников страницы, а не криптографическая гарантия: на статическом
сайте правильные ответы принципиально извлекаемы.

## Деплой на GitHub Pages

Workflow `.github/workflows/deploy.yml` собирает сайт в Docker и публикует через GitHub Pages.

1. Запушьте репозиторий на GitHub (ветка `main`).
2. В настройках репозитория: **Settings → Pages → Source → GitHub Actions**.
3. При пуше в `main` workflow соберёт сайт с `NUXT_APP_BASE_URL=/<имя-репозитория>/`.

Для кастомного домена добавьте переменную репозитория **Settings → Secrets and variables → Actions →
Variables → New variable**: `NUXT_APP_BASE_URL` = `/` (или другой подпуть).

Локальная проверка сборки под подпуть:

```bash
make build BASE_URL=/self-testing/
```
